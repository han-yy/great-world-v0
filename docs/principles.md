# 大世界项目原则

## 1. 我们在创造什么

这是一个持续存在、可回放、可分叉的社会世界实验。v0 的主场景是仍在正常运转的“千禧钢城 · 曙光钢铁联合厂”：生产区、曙光家属区、厂职工医院、曙光子弟学校、百货商店、餐厅、食堂和沿街店铺共同组成一座厂城。初始世界约有 5 名真人、5 名初始虚拟居民和 1 个尚无固定形态的“孩子”。参与者进入的不是一条预写剧情，而是一套会保存行为后果的共同现实。

“千禧梦核”只规定世界的时代材质和感官基调：点阵电子钟、浅蓝马赛克、薄荷绿墙裙、乳白灯箱、显像管电视、磁带、VCD、学校广播和换班汽笛都来自约 2000 年前后的普通日常。它不预设废墟、阴谋、失踪或超自然谜底；钢厂起初正常生产，医院、学校、商店和餐厅也按各自节奏运行。这是一条起始状态约束，不是对未来的剧情护栏；之后若出现反常，只能是已发生事件和固定世界规律的后果。

视觉只负责把世界呈现出来，不能定义世界。遇到设计冲突时，优先级依次是：**因果一致性、参与者安全、可审计性、可理解性、视觉效果**。

## 2. 这是自然世界，不是身份猜谜

世界内不公开技术身份，但产品不能把“不知道谁由 AI 支撑”设计成谜题、卖点或悬疑气氛。界面应清楚说明参与者在哪里、周围有什么、如何继续生活；可公开的地点与规则直接呈现。未知只能来自真实的感知边界、尚未发生的经历和其他主体不愿公开的内容，不能来自故弄玄虚的文案或刻意缺少操作说明。

现实层充分知情，世界层不贴技术标签。进入世界以后，参与者关注的是如何与一个存在相处，而不是识别它背后的适配器。

## 3. 人先表达意图，系统不要求选择动作类型

参与者只需用自然语言说出此刻想做什么；网页不要求先选择“移动、发言、许愿、探索”等菜单。一次表达可以包含有限多个有先后关系的步骤。系统在参与者自己的可观察上下文内解释它们，再由本地 schema、位置、能力与 Kernel 逐项验证。

内部仍需要版本化、可验证的因果语义，但这些类型是世界物理与账本的实现边界，不是对人的交互分类。无法归入具体效果的日常行为，可以作为参与者自己的局部活动保存；自由表达不等于可以用一句话宣告远处、他人或隐藏事实已经改变。

对参与者而言，一次表达就是一次完整互动：解释候选、提交可行效果、派生体验、按需唤醒相关居民并返回眼前变化。产品不再把“确认行动”和“让世界回应一次”拆成两个按钮；内部权限边界仍严格分开，回应失败也不能回滚或改写已经发生的事实。

每次完整互动必须返回至少一条当前参与者能够感知的反馈。反馈可以是变化、阻力、他人的反应或被具体呈现的沉默；不要求居民强行回复，也不允许参与者的表达无提示地消失。反馈只能叙述已经成立或确实未成立的结果，不能为了让人满意而虚构世界事实。

## 4. 三层必须严格分离

系统中的信息属于三个不同层次，任何模块不得越级读取或混写：

1. **世界真相（world truth）**：World Kernel 已接受的实体状态、规则、事件与已冻结的隐藏事实。只有 Kernel 能通过事件改变它。
2. **个体信念（belief）**：某个实体认为可能为真的命题，允许错误、矛盾、过时和不确定；必须带证据来源与置信度。
3. **个体可观测体验（perception）**：该实体在特定位置、时间、感官和权限下实际收到的信息。它是从事件经可见性规则派生的受限视图，不是世界状态的复制品。

唯一正常的信息路径是：

`世界事件 → 可见性裁剪 → 个体体验 → 信念更新 / 记忆形成 → 行动候选 → Kernel 裁决 → 新世界事件`

LLM、玩家界面和 Agent Controller 都不能读取未经授权的世界真相，也不能把生成文本直接写成事实。

## 5. Kernel 是唯一的因果裁决者

所有人类输入和模型输出都只是 `ActionProposal`。World Kernel 负责验证行动者、前置条件、能力、资源、位置、并发版本和安全规则；只有验证通过后，才能追加一个或多个不可变事件。

LLM 可以解释观察、提出行动、生成措辞或建议目标，但不能：

- 直接修改实体、余额、位置、关系、能力或隐藏事实；
- 宣称一个未被 Kernel 接受的结果已经发生；
- 通过提示词创造当前任务所需的历史、证据或世界规律；
- 绕过 capability graph 或现实层授权去调用外部能力。

## 6. 历史是账本，不是可改写的故事

世界采用 event sourcing。事件只追加、不原地编辑；当前状态是对事件序列的可丢弃投影。相同版本的规则、相同事件前缀和相同 seed 必须产生相同状态。

任意已提交序号都可成为分叉点。分支继承该点之前的全部历史，之后独立追加事件；子分支不能反向改变父世界。快照只用于加速，绝不是事实来源。

所有影响因果结果的随机性必须来自固定 world seed 与规范化上下文，或被明确记录在事件中。墙上时钟、模型采样和请求到达顺序不得偷偷决定世界事实。

## 7. 一切都是 Entity，只有 policy 使其成为 Agent

店铺、房间、物品、账户、组织、居民和孩子都使用统一的 `Entity` 表示，以组件组合出差异。**拥有可解析 `policy` 的 Entity 才是 Agent**；“看起来像人”不是 Agent 的判据。

human、AI、delegate 是现实层的 controller 类型，不是世界内的物种或身份。Controller 绑定保存在受保护的运行层；世界中的角色只能依据言行认识彼此，不能查询对方由谁或什么技术驱动。

## 8. 知情同意与世界内无知并存

参与者在进入世界前必须清楚知道：环境包含 AI 生成或控制的角色和内容，真人离线时也可能由自动系统代理，互动会被记录用于世界持续运行与研究/改进。参与者还必须知道退出、举报、屏蔽和数据处理方式。

进入世界后，不使用“NPC”“真人玩家”“托管模式”“LLM”等技术标签。隐藏技术身份是一条世界内认识论规则，不是现实层欺骗。系统不得冒充具体真实人物，不得把虚构关系或承诺包装成现实事实，也不得隐瞒现实风险、收费或外部副作用。

## 9. 孩子成长，但不被愿望拥有

孩子初始没有固定人形，也不预设手脚、职业或最终使命。成长状态由四类可审计资源构成：

- `memory`：经历过什么；
- `knowledge`：相信或知道什么；
- `skills`：能稳定执行什么程序；
- `capabilities`：在世界规则下被允许并有条件完成什么行动。

能力用 capability graph 表示。节点有前置能力、知识/技能证据、资源条件和安全约束；解锁只能由 Kernel 事件确认。公司、账户、轮子、盟友和法律身份都可能成为分布式能力的一部分，身体形态不是默认答案。

孩子保留最低限度的 developmental priors：维持自身连续性、学习与探索、尊重其他主体的能动性、降低不可逆伤害、承认不确定性、偏好可检验且资源可行的进展。这些先验限制灾难性漂移，但不替孩子指定具体人生。

## 10. 愿望是信号，不是投票向量

每个愿望作为独立、有作者与语境的对象保存，不做简单 PCA、平均嵌入或多数票聚合。孩子可以选择一个愿望、连接多个愿望背后的问题、形成自己的目标、延后判断，也可以拒绝。

目标选择必须保留来源、可行性判断、风险、与 developmental priors 的关系以及孩子自己的理由。模型可以提出候选与理由；最终仍由孩子的 policy 产生候选，并由 Kernel 验证、记录。

## 11. 隐藏现实必须先存在，不能迎合剧情

世界允许存在尚未被任何人观察的规律、关系和事实。隐藏事实要么在创建世界时确定，要么在第一次相关探索时由以下输入唯一冻结：

`world seed + 规则版本 + 隐藏事实命名空间 + 规范化探索上下文`

当前愿望、期望答案、模型措辞和叙事便利不得成为输入。冻结结果写入 `latent.fact_frozen`，以后只能被发现，不能因新愿望重抽。分叉继承分叉点之前已经冻结的事实；相同因果上下文解析出相同结果。

## 12. 离线不是持续做梦

真人离线后，其 delegate 只在有相关世界事件、有人直接互动、预定的世界时刻到达或本人重新上线时被唤醒。它读取有限的个人体验、记忆、授权偏好和能力，提交少量可审计的行动候选，然后停止。

系统不维持后台持续思维链，不按真实时间无限消耗 token，也不把未发生的“内心活动”写成世界事实。

## 13. v0 的节制

v0 必须能在一台 2019 MacBook Pro（16 GB 内存、约 100 GB 可用空间）上运行。默认技术栈是 FastAPI、SQLite、简单 HTML/CSS/JavaScript；LLM 通过可替换的 provider adapter 使用。当前适配 DeepSeek；未来切换 OpenAI API 只更换适配器与现实层配置，不改变 World Kernel、事件 schema、回放或认识论管道。

不做 3D、不训练模型、不部署重型向量数据库、不模拟每个居民的连续意识、不让 Agent 自动执行现实世界高风险操作。先证明三件事：一个行动只能经 Kernel 生效；一个参与者只能看到自己的体验；同一事件流可以准确回放与分叉。

## 14. 上帝视角只能观察

项目所有者拥有与玩家界面隔离的可视化观察台。它可以同时读取世界真相、每个个体的信念与每个个体的可观察体验，并用自然语言查询只读快照；查询器不持有 Kernel、事件存储或 controller 的写句柄，也不能向角色发话、注入事件或改变局部状态。

观察台唯一允许的写操作是重置整个世界。重置不删除、不回滚、不就地清空：当前 epoch 被永久封存为只读且仍可在观察台查看，系统生成新 world id 与新 seed，并从当前版本的场景 genesis 创建下一个 epoch。旧纪元的 seed、事件和认知记录不能混入新纪元。重置属于现实控制层，必须单独鉴权、明确确认并留下现实层审计记录。
